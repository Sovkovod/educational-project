# КАРТА ДАННЫХ — что где лежит

Этот файл отвечает на вопрос «где найти и где менять». Всё смысловое содержимое сайта
(команда, участники, навыки, проекты, контакты) живёт в четырёх JSON-файлах в `data/`.
В `index.html` остались только рамки и подписи интерфейса.

> Правило: **один факт — одно место.** Если текст про команду есть в JSON, не дублируйте
> его в разметке: разметка перезапишется при загрузке страницы.

## 3. Как данные попадают на страницу

```
data/*.json  ──fetch──►  Arcade.data.{site,crew,skills,scores}
                              │
                              ├─► applyTexts()    подставляет тексты в [data-site-text] и в контакты
                              ├─► renderAbout()   about[] + счётчики табло
                              ├─► renderCrew()    карточки участников в #crewGrid
                              ├─► renderSkills()  #directions + #skillSlots
                              └─► renderScores()  строки в #scoresBody
                                        │
                                        └─► событие arcade:ready, затем навигация/заставка
```

Ключевые факты (`js/data.js`):

- Файлы грузятся **целиком**, по одному на ключ (`data.js:97-116`), с `cache: 'no-store'` —
  правка JSON видна после обновления страницы, без пересборки.
- **Слияния нет.** Если файл загрузился, `Arcade.data.<ключ>` — ровно его содержимое.
  Удалённый из JSON ключ не «дозаполнится» значением по умолчанию.
- `FALLBACK` (`data.js:36-88`) — встроенные демо-данные. Они включаются **только если файл
  не загрузился** (открыли `index.html` как файл, нет сервера, 404). Тогда вверху страницы
  появляется плашка «ДЕМО-РЕЖИМ» (`data.js:520-531`).
- Значит локальная проверка — только через сервер:
  `python -m http.server 8080` (или `docker compose up`), затем `http://127.0.0.1:8080`.

Что хранится в браузере: **ничего, кроме настройки звука** — `localStorage['arcade:sound']`
(`js/nav.js:12,77`). Базы данных, API и бэкенда нет: сайт — статика.

## 4. `data/site.json` — команда, тексты, контакты

Корень — объект с тремя блоками: `team`, `site`, `contacts`.

| Ключ | Тип | Где видно на странице |
|------|-----|------------------------|
| `team.title` | строка | шапка `HUD`, `HIGH SCORE`, заголовок заставки `#bootTitle`, `<title>` вкладки, скрытый `<h1>` |
| `team.shortName` | строка | **нигде** — задел на будущее |
| `team.motto` | строка | строка под названием на табло `HIGH SCORE` |
| `team.university` | строка | табло и подвал |
| `team.group` | строка | **нигде** — задел на будущее |
| `site.event` | строка | `<h1>`, табло, подвал заставки, подвал страницы, `<title>` |
| `site.about` | массив строк | уровень 0, «О КОМАНДЕ» — печатается по одной строке |
| `site.crewLead` | строка | подзаголовок под «ВЫБЕРИТЕ ИГРОКА» |
| `site.levelCaption` | строка | подпись под пиксельным пейзажем |
| `site.copyright` | строка | подвал |
| `contacts.captain` | строка | блок КАПИТАН на уровне 4 |
| `contacts.email` | строка | `mailto:` кнопки PLAY AGAIN + aria-label |
| `contacts.telegram` | URL или `""` | ссылка `telegram →`; пусто — ссылка скрыта |
| `contacts.repo` | URL | **адрес** ссылки SECRET CODE |
| `contacts.repoLabel` | строка | **видимая подпись** той же ссылки |

`contacts.repo` и `contacts.repoLabel` — два независимых поля (`data.js:146-150`): адрес и
текст. Их легко рассинхронизировать — см. ловушку № 1.

## 5. `data/crew.json` — участники

Массив объектов. Порядок в массиве = порядок карточек и порядок листания в профиле.
Сейчас в команде 4 игрока (`player1`…`player4`).

| Поле | Тип | Смысл и ограничения |
|------|-----|---------------------|
| `id` | строка | Контракт. `player1`… — на него ссылаются `owners` в `skills.json`. Уникальный, не меняется |
| `name` | строка | Имя на карточке и в профиле |
| `class` | строка | Бейдж на портрете (игровой класс) |
| `group` | строка | Строка под именем, до разделителя `·` |
| `role` | строка | Роль после `·`, жирным |
| `stats` | объект | 3–4 пары «название: 0–10». Названия — любой текст, значение режется по 0–10, рисуется 10 сегментов |
| `inventory` | массив id | Берутся из `skills.json`: оттуда иконка и подпись. Незнакомый id не ломает карточку — покажется как есть с иконкой по умолчанию |
| `sprite` | путь | `assets/sprites/*.png`, показывается 96×96 без сглаживания |
| `contact` | URL | Кнопка «КОНТАКТ ↗» в профиле. Пусто → подставляется `contacts.telegram`; нет и его → «Контакт не указан» |
| `bio` | строка | Абзац в профиле |

Производные значения считаются сами: `POWER` в профиле = сумма `stats` (максимум —
`stats.length × 10`), счётчик `PLAYERS` на табло = длина массива, номер `P1…Pn` — по порядку.

## 6. `data/skills.json` — навыки команды

Два независимых блока.

**`directions`** — агрегированные шкалы (уровень 2, левая колонка):

```json
{ "id": "backend", "label": "BACKEND", "value": 8 }
```

`value` 0–10 → процент в подписи и 20 сегментов шкалы.

**`slots`** — группы плашек (уровень 2, правая часть):

```json
{ "id": "languages", "label": "ЯЗЫКИ", "items": [
  { "id": "python", "label": "PYTHON", "level": 8, "icon": "scroll",
    "owners": ["player1", "player3"] }
] }
```

| Поле | Смысл |
|------|-------|
| `slot.label` | Заголовок группы плашек |
| `item.id` | Ключ, которым навык указывается в `crew.json → inventory` |
| `item.label` | Надпись на плашке и подпись иконки |
| `item.level` | 0–10, печатается как `LVL n` |
| `item.icon` | Имя файла без префикса: `scroll` → `assets/sprites/icon-scroll.png` |
| `item.owners` | Список id участников — **справочно** |

> Важно: фильтр «кто владеет навыком» (`data.js:341-372`) на самом деле смотрит в
> `crew.json → inventory`, а не в `owners`. `owners` нужен, чтобы данные не разъезжались,
> и чтобы человек видел связь. Рассинхрон не сломает сайт, но введёт в заблуждение — см. ловушку № 3.

## 7. `data/scores.json` — проекты и достижения

Массив объектов, каждый — строка таблицы HIGH SCORES. Порядок = место в рейтинге (`01`, `02`, …).

| Поле | Тип | Смысл |
|------|-----|-------|
| `id` | строка | Уникальный; используется в id раскрывающейся строки (`det-<id>`) |
| `name` | строка | Название проекта (CAPS по стилю) |
| `status` | `"CLEARED"` \| `"LOCKED"` | Зелёный бейдж или серый с замком |
| `stack` | массив строк | Чипы технологий в раскрытой строке; пусто — блок скрыт |
| `role` | строка | Роль команды: мелкая строка под названием и поле в деталях; пусто — скрыто |
| `desc` | строка | Описание «ЧТО ЭТО» |
| `shot` | путь или `""` | Скриншот 180×101 в деталях; пусто — текст на всю ширину |
| `link` | URL или `""` | Ссылка «открыть проект →»; пусто — кнопки нет |

Клик по строке раскрывает детали; пустой массив `scores` показывает заглушку
«Проектов пока нет — добавьте их в `data/scores.json`».

## 8. Соответствие «элемент страницы ↔ источник данных»

| Элемент `index.html` | Что подставляет | Источник |
|----------------------|-----------------|----------|
| `#bootTitle`, `.hud__team`, `.hiscore__name` | название команды | `team.title` |
| `.hiscore__motto` | девиз | `team.motto` |
| `#aboutText` | абзацы с печатной машинкой | `site.about[]` |
| `#statPlayers` | число участников | длина `crew.json` |
| `#statSkills` | число навыков | сумма `skills.slots[].items[]` |
| `#statScores` | число проектов | длина `scores.json` |
| `#crewGrid` | карточки участников | `crew.json` целиком |
| `#directions` | шкалы направлений | `skills.directions[]` |
| `#skillSlots` | плашки навыков | `skills.slots[]` |
| `#scoresBody` | таблица проектов | `scores.json` целиком |
| `#playAgain` | `mailto:` капитана | `contacts.email` |
| `#telegramLink` | ссылка TG | `contacts.telegram` |
| `#repoLink` | адрес + подпись | `contacts.repo`, `contacts.repoLabel` |
| `[data-site-text="..."]` | точечная подстановка по пути | `site.json` |

Механика точечной подстановки: любой элемент с атрибутом `data-site-text="team.title"`
получает значение по этому пути (`data.js:118-123`). Добавили в JSON новый ключ — можно
вывести его в разметке, дописав такой же атрибут, без правок JS.

## 9. Ассеты: имена имеют значение

Иконки инвентаря и навыков берутся по соглашению об имени — файл `icon-<icon>.png`:

```
icon-arrow · icon-coin · icon-gem · icon-key · icon-lock
icon-potion · icon-scroll · icon-shield · icon-sword
```

Портреты участников (`assets/sprites/*.png`): `mage`, `ranger`, `knight`, `engineer`.
Пиксельные, квадратные, масштабируются без сглаживания.

Прочее: `assets/img/level-bg.png` (пейзаж уровня 0), `logo-emblem.png`, `favicon.png`,
`shot-placeholder.png` (заглушка скриншота), шрифты в `assets/fonts/`.
`docs/screenshots/*.png` использует только README — на сайт они не влияют.

Новый спрайт: положите файл в `assets/sprites/` и укажите путь в `crew.json → sprite`.
Новая иконка: файл `icon-<имя>.png` + имя в `skills.json → icon`.

## 10. Что НЕ в данных

Правится прямо в `index.html` (это каркас интерфейса, а не контент):

- заголовки уровней: `О КОМАНДЕ`, `ВЫБЕРИТЕ ИГРОКА`, `НАВЫКИ КОМАНДЫ`, `ПРОЕКТЫ`, `КОНТАКТЫ`;
- служебные надписи: `INSERT COIN`, `PLAYERS / SKILLS / SCORES / LEVELS`, `PROFILE ▶`,
  `ЗАКРЫТЬ · ESC`, подсказки в подвале;
- тексты терминала-пасхалки (клавиша `T`) — `js/nav.js`;
- логотип в блоке HI-SCORE: `инфографика/логотип/lockup-v-dark.svg` — название и подпись
  запечены в SVG, поэтому при смене названия команды пересоберите его
  (`python инфографика/make_logo.py`);
- alt-тексты, aria-подписи, порядок блоков, количество уровней.

## 11. Рецепты

**Добавить игрока**
1. `data/crew.json` — новый объект в конец массива, `id` уникальный (`player5`).
2. `stats` — 3–4 навыка, значения 0–10.
3. `inventory` — только id, существующие в `skills.json` (иначе иконка будет по умолчанию).
4. `sprite` — новый файл в `assets/sprites/` или существующий портрет.
5. `contact` — `https://t.me/…`; пусто — возьмётся Telegram капитана.
6. Обновить счётчик в тексте `site.crewLead` («Пять игроков в составе»). Цифра на табло
   `PLAYERS` пересчитается сама.
7. При желании дописать `id` в `owners` нужных навыков в `skills.json`.

**Добавить навык**
1. `data/skills.json` → `slots[]` → `items[]` — новая плашка (`id`, `label`, `level`, `icon`).
2. Выдать его участникам: `crew.json → inventory` (это и есть источник правды для фильтра).
3. Синхронизировать `owners`.
4. Счётчик `SKILLS` на табло и фильтр обновятся сами.

**Добавить проект**
1. `data/scores.json` — объект с уникальным `id`, `name`, `status`, `desc`.
2. Заполнить `stack`, `role`, `shot`, `link` по желанию (пустые поля просто не выводятся).

**Сменить контакты**
1. `data/site.json → contacts`: имя, почта, Telegram, репозиторий.
2. Для репозитория — **оба** поля: `repo` (куда ведёт) и `repoLabel` (что написано).

## 12. Ловушки (уже случались)

1. **Адрес и подпись ссылки могут разъехаться.** `contacts.repo` — куда ведёт ссылка,
   `contacts.repoLabel` — что на ней написано; это два независимых поля. Заполняйте оба одним
   адресом: иначе ссылка выглядит как один сайт, а уводит на другой. Так уже случалось —
   подпись была на GitHub, а адрес вёл на главную страницу GitVerse.
2. **Число игроков в тексте — вручную.** `site.crewLead` («Четыре игрока в составе») не
   пересчитывается; табло `PLAYERS` пересчитывается. Добавили игрока — поправьте фразу.
3. **`owners` против `inventory`.** Фильтр навыков смотрит в `inventory`; `owners` — только
   справка. Рассинхрон не ошибка, но подпись «кто владеет» и данные будут расходиться.
4. **JSON целиком заменяет демо-данные.** Убрали ключ — он пропадёт с сайта, а не
   подставится из `FALLBACK`.
5. **Открыли как файл.** `file://…/index.html` → JSON не грузится → плашка «ДЕМО-РЕЖИМ»
   и совсем другие тексты. Проверяйте только через локальный сервер.
6. **Запятая в конце JSON** — файл не загрузится, страница молча уйдёт в демо-режим.
   Проверка: `python -m json.tool data/crew.json`.
7. **Опечатка в имени иконки или спрайта** — битая картинка без ошибки в консоли
   (путь собирается из имени).
8. **Дубли `id`** в `crew.json` или `scores.json` — карточки/строки начнут конфликтовать
   (профиль откроется не тот, детали раскроются не там).
